# 统一充值为快速充值与限时链上充值

## Goal

重构整个充值配置和使用流程，只保留快速充值、按币种数量占用地址组合 30 分钟的链上充值。合并后台重复的充值地址池、充币网络、充值网络配置和限时链上充值配置，取消旧永久地址分配入口与新增分配能力。

## What I already know

- 用户明确只保留两种充值方式，授权重新设计整个充值逻辑与后台管理。
- 限时充值沿用已确认规则：网络＋链上资产＋地址＋精确数量组合占用 30 分钟；不同金额共址，同金额换址；满池不改金额；过期未付历史引起的歧义到账转人工。
- 首批仍为 Ethereum、Base、Tron、Bitcoin、Solana，仅开放明确配置的资产；每网络地址数量可扩容，10 不是硬上限。
- 上一任务已交付限时充值引擎与三端页面，但后台仍有旧配置/地址分配并存，需统一业务模型和入口。

## Assumptions

- 用户确认当前为测试环境，不需要旧永久地址兼容；移除旧分配和到账路径，保留新订单账务与提现行为。
- 快速充值沿用已有服务商支付协议；提现网络与其他钱包业务不因充值重构受影响。
- 优先复用已有监听和账务实现，移除旧新建路径并整合配置，而非重写已验收的资金处理。

## Open Questions

- 无。2026-10-23 用户明确取消旧地址兼容要求，直接重构充值。

## Requirements

- 用户端仅展示快速充值、链上充值两条流程。
- 后台链上充值集中维护网络状态、节点、币种映射、收款地址、订单与待核对到账。
- 新收款地址直接归属网络，不再有向用户永久分配地址的操作，也不要求人工再将库存编号纳入另一份共享池配置。
- 兼容已有已配置的限时充值数据，不删除资金历史、不改变已经确认的占用和归属规则。
- 现存旧配置入口收敛或兼容跳转；后端不能保留可绕过新模型创建永久地址分配的公开路径。

## Acceptance Criteria

- [x] 后台操作人员在一个链上充值工作区完成网络、资产、节点和地址维护，不再在重复页面之间配置。
- [x] 快速充值保持可用；Mobile/PC 链上流程均遵循先输入币种数量再创建订单。
- [x] 永久分配入口及新建 API 停用，已有历史账务不丢失。
- [x] 地址直接添加/批量导入、停用、扩容有明确权限、校验、审计和异常处理。
- [x] 配置与用户准入使用同一数据规则，五网络监听、30 分钟占用及人工核对回归通过。
- [x] 相关类型、行为、路由/实库、构建和浏览器验证完成；遗留门禁明确记录。

## Out of Scope

- 私钥、归集、提现改造、删除历史财务记录、生产数据迁移执行或部署。
- 修复无关秒合约、新币功能或既有后台全量包体问题。

## Definition of Done

完成相关源码与必要的新迁移、回归验证、运维说明、项目规范和 PROGRESS 记录。不得修改已经应用的 0158/0159 迁移。

## Technical Approach / Decision

- 后台仅两个充值导航入口：链上充值（网络配置、订单/到账核对、入账流水标签）与快速充值（配置、订单标签）。各标签按现有权限独立挂载，不预读未授权页面。
- 链上配置按网络集中展示节点、开放状态、明确链资产映射与直接添加/批量导入地址；删除库存编号预览和二次纳入操作。地址仅启停，不编辑链身份、不回收给其他人。
- 新准入以 scanner + chain_assets + shared_addresses + 平台资产费用/开关为权威，不依赖旧网络白名单或每地址的旧分配范围。旧 network_configs 因提现仍依赖而保留，以提现网络入口维护，不再是链上充值开关。
- 节点已配置时继续跟进历史订单；网络 enabled 只决定是否接受新充值。修改配置依然增加 revision 并使旧扫描失效。
- 直接地址批量接口校验完整批次与规范地址，网络锁下原子写入独立收款地址及审计；重复导入不重复创建也不自动重新启用停用地址。地址以网络独立管理，重复导入不会覆盖已有配置。
- 移除用户端永久分配路由及实现，旧后台地址维护和旧观测到账路径一并移除；旧页面跳转新工作区。网关旧充值回执明确拒绝并记录，不再按永久归属入账。
- 不删除历史表，不改已应用迁移；新增 0160 解除收款地址与旧永久库存的外键，收款地址自行生成编号，保留已有链上订单引用。

## Implementation Plan

1. 统一地址直接管理和充值准入，退役永久分配写入口；实库及权限回归。
2. 后台两工作区、网络集中配置与地址批量操作、旧 URL 跳转、提现配置隔离；前台两方式命名与遗留调用清理。
3. 类型/lint/行为/构建、实库资金/配置、浏览器桌面/窄屏验收，更新规范、运维说明和进度。
