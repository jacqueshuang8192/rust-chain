# 手机端历史记录统一分页

## 目标

完善手机端历史记录浏览能力，优先覆盖提现、现货订单、杠杆订单/持仓、闪兑、理财、贷款、预测、快捷充值等固定 `limit` 的列表，避免用户在超过默认条数后看不到更早记录。

## 范围

- 先复用现有秒合约历史和钱包账单的分页状态模式。
- 后端接口优先采用稳定的 `limit + offset`，响应返回 `has_more` 或可计算的 `total`；如果某模块已有分页契约则保持其既有响应格式。
- 手机端统一提供首屏加载、继续加载、追加失败重试、切换账号/筛选重置、重复数据去重和加载状态。
- 记录列表按服务端稳定排序追加，不改变现有状态筛选、金额精度和业务操作。
- 补充核心分页控制器/适配器测试，验证跨页追加、重复页、乱序响应、会话切换和失败重试。

## 非目标

- 不改交易撮合、结算、资金记账、状态机或历史数据。
- 不把 `limit` 无上限调大替代分页。
- 不为本轮新增导出、复杂筛选或桌面端重构。
- 不处理已具备分页的秒合约历史和钱包账单，除非需要抽取无行为变化的共享基础能力。

## 验收标准

- 提现、现货、杠杆、闪兑、理财、贷款、预测、快捷充值中纳入范围的列表可连续加载超过首屏上限。
- 跨页无重复、无静默跳过；末页正确停止继续加载。
- 切换状态/账户/页面或退出登录时，旧请求不能覆盖新列表。
- 追加失败只影响追加操作，可单独重试，不丢失已显示数据。
- 现有金额以十进制文本显示，分页参数和记录 ID 做安全整数校验。
- 通过最贴近的 Mobile 类型检查、分页测试和相关后端测试；未覆盖的真实生产容量边界需明确记录。
