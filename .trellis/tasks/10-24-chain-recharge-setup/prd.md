# 链上充值扫描与管理员配置优化

## Goal
参考 GMPay Edge 分层配置，优化现有五网络的扫描接入、支付方式与地址管理，让管理员知道怎样配置及为何不可收款。

## Scope / assumptions
- 用户已明确选择链上交易扫描：配置节点、监听币种、收款地址，并清楚显示是否能正常收款。
- 保留快速充值 + 链上充值、币种精确数量、30 分钟组合占用、到期释放及歧义人工核对。
- 本轮优化现有五网 HTTP 扫描配置，不新增交易所支付、法币报价、WSS、Webhook、多节点切换或扫描协议。

## Requirements
- 提供节点 → 监听币种 → 收款地址 → 扫描确认的配置指引，已有编辑入口/权限/草稿/CAS 保持。
- 网络与币种支付方式显示配置状态和明确阻塞原因，支持平台币种开关、网络接单、地址和扫描新鲜度区分。
- 服务端返回数据库时间核对的扫描新鲜度与持久扫描高度；后台显示检查时间，不用浏览器时间推测网络是否正常。
- 支持 Alchemy/Helius 单独填写服务商 API Key 并生成原有加密节点 URL；手动节点和 TronGrid 头密钥保持。
- 自动刷新只在没有编辑或写操作时运行；写操作和主动刷新保持原权限。
- 不将配置完成当成实链验证，不实现假连接测试。

## Acceptance Criteria
- [x] 五网状态说明及配置引导可操作、支付方式阻塞原因正确。
- [x] 服务商密钥草稿生成/切换/取消安全，保存仍显式确认。
- [x] 后端扫描状态真实且不回传凭据，不改变扫描游标或入账。
- [x] 定向/全量前端及相关后端检查通过，浏览器桌面/窄屏验证与进度记录完成。
